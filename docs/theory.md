# Минимум теории

Всё, что нужно, чтобы понимать код базовой версии и разговаривать с Парфеновым на одном языке. Все примеры проверены программой (`demo` и тесты).

## 1. Что такое rank и select

Выпишем все объекты (например, все перестановки длины n) в определённом порядке и пронумеруем с нуля.

- **rank(x)** — номер объекта x в этом списке;
- **select(r)** (в статьях — *unrank*) — объект с номером r.

Это взаимно обратные функции: `select(rank(x)) = x`. Главное — считать их **без выписывания списка**: перестановок длины 30 больше, чем 10³².

Зачем это нужно:

1. **Компактное хранение.** Объект хранится одним числом из ⌈log₂ N⌉ бит, где N — число всех объектов. Меньше нельзя: это теоретический минимум (связь с базами данных).
2. **Параллельный перебор.** Поток №i перебирает номера с a по b: select даёт ему стартовый объект.
3. **Случайный объект с равной вероятностью:** случайный номер, затем select.
4. **Сжатые структуры данных** (см. раздел 6).

## 2. Перестановки: код Лемера и факториальная система счисления

**Код Лемера** перестановки p: d_i = сколько элементов правее p_i меньше p_i. Всегда 0 ≤ d_i ≤ n−1−i, и

> rank(p) = d₀·(n−1)! + d₁·(n−2)! + … + d_{n−1}·0!

Это запись номера в **факториальной системе счисления**.

**Пример.** p = (2, 0, 3, 1), n = 4.
- d₀ = 2 (правее двойки меньше неё 0 и 1), d₁ = 0, d₂ = 1 (правее тройки — 1), d₃ = 0.
- rank = 2·3! + 0·2! + 1·1! + 0·0! = 12 + 1 = **13**.
- Проверка «на пальцах»: перед p стоят все 6 перестановок, начинающихся с 0, все 6 — с 1, и одна с 2: (2, 0, 1, 3). Итого 13.

**select(13, n = 4)** — то же в обратную сторону:
- 13 = 2·3! + 1 → d₀ = 2; 1 = 0·2! + 1 → d₁ = 0; 1 = 1·1! → d₂ = 1; d₃ = 0.
- Из (0, 1, 2, 3) берём элемент №2 → **2**; из (0, 1, 3) — №0 → **0**; из (1, 3) — №1 → **3**; остаётся **1**.
- Ответ (2, 0, 3, 1).

**Где тратится время.** Номер считается в два шага, и их стоит ускорять по отдельности:

| Шаг | Как у нас | Что известно в теории |
|---|---|---|
| перестановка ↔ код Лемера | наивно O(n²); деревом Фенвика O(n log n) | O(n log n / log log n) (Dietz); O(n) на word-RAM (Mareš & Straka, 2007) |
| код Лемера ↔ число | n умножений/делений на маленькое число | «разделяй и властвуй» через быстрое умножение длинных чисел |

Пока номер помещается в 64 бита (n ≤ 20), второй шаг почти бесплатный. Дальше это **длинная арифметика**, и каждый из n шагов проходит по всему числу длиной ≈ n log₂ n бит. В сумме выходит квадратичное время, и на практике именно оно доминирует (см. [benchmarks.md](benchmarks.md)).

**Myrvold & Ruskey (2001).** Если отказаться от лексикографического порядка, хватает O(n) операций:
- select: начинаем с (0, 1, …, n−1); для m = n, n−1, …, 1 меняем местами p[m−1] и p[r mod m], затем r = r div m;
- rank: «откатываем» эти обмены с конца, используя обратную перестановку, и собираем остатки обратно в число.

## 3. Сочетания: комбинаторная система счисления

Сочетание из n по k — возрастающий набор c₀ < c₁ < … < c_{k−1} из чисел 0..n−1.

**Колексикографический порядок (colex)** — сравниваем с конца, по наибольшему элементу. Номер:

> rank_colex(c) = C(c₀, 1) + C(c₁, 2) + … + C(c_{k−1}, k)

**Пример.** n = 5, k = 3, c = {0, 2, 4}: C(0,1) + C(2,2) + C(4,3) = 0 + 1 + 4 = **5**.

Почему так: сочетаний с наибольшим элементом меньше 4 ровно C(4, 3) = 4 (выбираем 3 числа из {0, 1, 2, 3}). Среди сочетаний с наибольшим 4 тех, у кого средний элемент меньше 2, — C(2, 2) = 1. Меньших по первому элементу нет: C(0, 1) = 0.

**select (жадно):** для i = k, k−1, …, 1 берём наибольшее x, для которого C(x, i) ≤ r, записываем c_{i−1} = x и вычитаем C(x, i) из r.

**Лексикографический порядок (lex)** сводится к colex отражением x → n−1−x (с разворотом набора):

> rank_lex(c) = C(n, k) − 1 − Σ C(n−1−c_i, k−i)

Пример: 10 − 1 − (C(4,3) + C(2,2) + C(0,1)) = 10 − 1 − 5 = **4**.

**Длинные числа.** Биномы не храним, а пересчитываем соседними шагами, например C(m−1, j) = C(m, j)·(m−j)/m: деление всегда нацело. Получается O(n) операций с длинными числами. Genitrini & Pépin (2021) показали, что именно из-за длинной арифметики классические оценки сложности этих алгоритмов занижены, и разобрали, как это исправить.

## 4. Пределы встроенных типов

Проверено вычислением:

| Что | 64 бита | 128 бит |
|---|---|---|
| перестановки (n!) | n ≤ 20 | n ≤ 34 |
| сочетания (все C(n, k)) | n ≤ 67 | n ≤ 131 |

Номер перестановки при n = 1 000 000 — это число примерно из 18,5 млн бит (2,2 МБ).

## 5. Куда двигаться дальше

Предварительно, до того как Парфенов даст статьи:

- **Быстрая длинная арифметика.** Перевод «код Лемера ↔ число» методом «разделяй и властвуй» (дерево произведений) с умножением Карацубы вместо n проходов по числу. Главный резерв ускорения на больших n.
- **Другие порядки:** коды Грея (соседние объекты отличаются минимально), Steinhaus–Johnson–Trotter для перестановок, «вращающаяся дверь» для сочетаний.
- **Перестановки с ограничениями:** беспорядки (без неподвижных точек) и задача о супружеских парах — Kagey; классы перестановок, избегающих шаблонов длины 3 — Hassler & Vajnovszki (2026), где эффективная реализация названа открытой задачей.
- **Другие объекты:** сочетания с повторениями, размещения, перестановки мультимножеств.

## 6. Вторая трактовка rank/select: сжатые структуры данных

Для битового вектора B: **rank₁(i)** — сколько единиц среди первых i бит, **select₁(j)** — позиция j-й единицы. На этих двух операциях строят сжатые индексы, в том числе в базах данных.

Связь с темой: в структуре RRR (Raman, Raman, Rao) каждый блок из b бит хранится как пара «число единиц c + номер блока среди всех C(b, c) блоков с c единицами», то есть через rank сочетания. Свежие работы: Dönges & Puglisi (SEA 2025) пробуют нелексикографические порядки сочетаний для RRR, Garg (2026) строит Парето-анализ «память/время» для rank/select.

Какую трактовку имеет в виду Парфенов (или обе), нужно уточнить: от этого зависит половина проекта.
