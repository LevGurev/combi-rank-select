# Как работаем

## Git за пять минут

Проще всего через **GitHub Desktop** (бесплатно, без командной строки).

1. *File → Clone repository* — скачать проект к себе.
2. *Current branch → New branch* — своя ветка на каждую задачу: `имя/задача`, например `timur/lehmer-proof`.
3. Поменяли файлы → внизу слева коротко описали изменения → *Commit*.
4. *Push origin* → *Create Pull Request*.
5. GitHub сам соберёт проект и прогонит тесты на Linux и Windows. Зелёная галочка — всё хорошо, красный крестик — что-то сломалось (нажмите на него и посмотрите, что именно).
6. Кто-то из команды смотрит изменения и нажимает *Merge*.

Ветка `main` всегда должна собираться и проходить тесты. Напрямую в `main` не пишем.

## Правила работы с нейросетями

1. **Давайте модели сам текст статьи (PDF), а не название.** Иначе она начнёт додумывать детали, особенно для свежих статей.
2. **Просите объяснение,** а не только код: «объясни каждую строку», «почему это верно», «разбери пример на n = 4».
3. **Любой алгоритм — только вместе с тестом перебором:** для маленьких n перебрать все объекты и сравнить номера. Такой тест ловит почти все ошибки, в том числе ошибки ИИ.
4. **Не добавляйте код, который не можете объяснить.** На защите спросят.
5. **В описании pull request пишем, где помогал ИИ.** Прозрачность лучше сюрпризов.
6. **Секреты не коммитим:** токены ботов, пароли, ключи. `.gitignore` уже настроен на `.env` и `secrets/`.

## Как добавить новый алгоритм

1. **Конспект:** `docs/papers/<автор>-<год>.md` по шаблону [`TEMPLATE.md`](papers/TEMPLATE.md).
2. **Код:** `include/combi/…`. Названия в общем стиле: `perm_rank_xxx<Num>` / `perm_unrank_xxx<Num>`, `comb_rank_xxx_big` / `comb_unrank_xxx_big`.
3. **Тесты** в `tests/`:
   - полный перебор при маленьких n (как `check_all_lex` в `test_permutations.cpp`);
   - `select(rank(x)) == x` на больших n;
   - совпадение с уже проверенными методами там, где порядок тот же.
4. **Замер:** одна строка `measure(...)` в `bench/bench.cpp`.
5. **Pull request:** что сделано, по какой статье, как проверено, где помогал ИИ.

## Эталонные значения

Числа в тестах для больших n посчитаны независимой реализацией на Python: `python3 tools/reference.py`. Скрипт сначала сам проверяет себя перебором. Новые эталоны добавляйте туда же.
